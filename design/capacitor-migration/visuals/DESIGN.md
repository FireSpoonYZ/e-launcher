# 非 Launcher 移动界面实现参考

本目录的 7 张设计图已生成并逐张查看。它们是布局与组件参考，示例会话、模型、包名和 OAuth 问题不写死到正式业务数据。功能范围以 `../README.md` 和现有业务实现为准。用户明确不要新增 UI 测试；通过类型检查、构建和真实设备操作检查实现。

## 参考来源

- Pi WebUI：<https://github.com/xing-shuyin/pi-web-ui>，已查看 `assets/chat-prompts.jpeg`。借鉴底部输入、模型与思考选择、工具内容展开、会话导航；将桌面多栏收为手机单栏，不照搬密集顶部导航与透明背景。
- Pi Desktop：<https://github.com/FaqFirebase/pi-desktop>，搜索资料描述其流式聊天、折叠工具、项目和设置；本次没有成功取得其页面截图，不能声称逐像素参照。
- ChatGPT App：借鉴手机聊天的开放阅读区域、底部输入和侧边会话导航；不复制品牌素材。

## 统一尺寸与颜色

设计图比例不完全一致，按逻辑宽度 390 CSS px 提取尺寸，不把图片像素直接当 CSS px。

| 项目 | 浅色 | 深色 |
| --- | --- | --- |
| 页面 | `#faf9f6` | `#191b19` |
| 表面/用户消息/输入区 | `#efeee9` | `#252925` |
| 主要文字 | `#242622` | `#eeeee8` |
| 次要文字 | `#70756f` | `#aab0a8` |
| 分隔线 | `#e5e5df` | `#343934` |
| 强调 | `#627565` | `#91ab93` |
| 选中背景 | `#e1e7df` | `#334237` |

使用系统 sans-serif（中文继承系统字体），正文 16px / 1.65，次要文案 13–14px，页面标题 24–28px / 1.25 / 650，栏标题 18px / 600。代码使用系统 monospace 13–14px。不要通过固定根字号覆盖系统字体缩放。

页面横向留白 20px，小屏可 16px；标题栏至少 56px；可点击图标占 44×44px；列表普通行 56px，双行约 68px；分组间距 28–32px。输入字段/按钮圆角 12px，用户气泡 20px，聊天输入容器 24px，底部面板上角 24–26px。只使用细分隔线与极轻面板阴影，不引入渐变和背景纹理。图中生成产生的细微纹理不实现。

主按钮浅色主题为深色填充与浅色字，深色主题反转；选择状态/辅助动作使用 sage。危险动作与错误使用明确红色文字，不只靠颜色表达状态。图标用同一套 20–22px 线性 SVG，不用 emoji 充当 UI 图标。

真实 Android 状态栏与导航栏由宿主管理，React 不画图中的时间、信号、电量和底部手势条。安全区只加一次。输入框随可见视口/键盘收缩；底部操作区不能遮正文或编辑内容。

## 1. chat-light.png：聊天

顶栏左菜单，中间 Pi/模型选择，右新会话；助手内容直接排在背景上，用户内容右对齐，最大宽 88%。图中正文与工具之间留白约 24px，段落约 14px。工具是一条可展开摘要，不把每段消息包成卡片。完成、执行中、失败均显示真实状态。助手动作放在正文下方的轻图标行。

输入区固定于内容区底端，圆角浅表面；加号和语音在左，发送/停止圆按钮在右。图片里这些按钮占用了文本横向空间；实现用可增长 textarea 与下方工具行，保证中文输入可读和长消息不挤压操作。思考强度置于输入附近，真实当前模型显示在顶栏。空态只给简洁提示，不放假的示例消息。流式更新时保留用户滚动位置，接近底部才跟随。

会话抽屉沿用同样的平面列表：顶部搜索/新建，中间会话标题与日期，当前会话淡 sage 选中，底部设置入口。删除为明确确认动作。抽屉不覆盖后丢失草稿，点击遮罩/Back 关闭。

## 2. settings-light.png：设置首页

背返回与大标题，下方分三组：偏好（通用、外观、桌面与手势）；AI 与工具（服务商与模型、技能、MCP、扩展）；高级配置与关于。标题左图标，右 chevron，双行副标题用次要色。不是每一行一张卡片，分组用空白和横线。

子页面同样使用简单字段行和明确分组。开关、选择、数字、文本按真实 schema 的类型展示；高级 JSON 是补充入口，不代替已有具体表单。桌面与手势页展示实时权限和连接状态，并调用原生系统动作。外观显示系统/浅色/深色，背景模式/图片/遮罩预览。普通界面不显示凭据原文。

## 3. history-light.png：会话树

标题与会话名下方是可滚动树，连接线 1px，圆节点，每层缩进 20–24px。长树允许横向滚动或控制缩进，不使文字缩到不可读。当前选中预览行用 sage 选中底色和左边线；当前执行路径和预览节点可以不同。

下方预览面板约 40% 高度（可滚动），标题、角色、Markdown 正文、复制，再给“从这里继续”主按钮。用户节点的动作应为编辑并续接，不能误标成助手继续。点击节点只预览，动作按钮才改会话位置；生成期间仍能预览，切换位置需要先停止。图中示例文字均由真实节点替代。

## 4. editor-light.png：高级文件编辑与冲突

顶部保存按钮；下一行全局/工作区分段选择；文件名、修改状态；格式化/上一版/导出工具行；剩余区域为大文本编辑区。按真实能力加入新建/导入、文件选择和分组字段入口。编辑区不嵌套卡片。

冲突是底部可见的琥珀色说明区域，提供保留草稿/重新载入。重新载入前保留当前编辑内容，不能直接覆盖草稿；重新加载并合并由用户明确操作完成。原文件 expected/base 必须交由 PiConfigStore CAS，绝不能把重新读取的 base 自动换上再盲写。JSON 格式化由原生 ConfigJson 保留数字写法，不能用 JS parse/stringify 处理整份配置。

正文留白是编辑空间，不是固定高度的空占位。顶部保存、返回脏提示、草稿恢复、上一版原文都必须真实接通。

## 5. model-dark.png：深色底部模型选择

深色示例展示同一颜色系统的反转：背景遮罩、面板上角、拖拽条、标题和关闭按钮、当前会话范围提示、模型搜索、provider 分组、模型行与选中勾选、思考强度分段选择、管理服务商、完成按钮。

图中固定的两个模型与四种强度只用于视觉；实际列表/可用 thinking values 来自当前模型能力，保留现有全部合法选项和当前会话/启动默认值区别。面板 max-height 按视口限制，内容滚动，底部按钮可见。背景图片里的问候文字是生成模型添加的占位，不复制到业务。

## 6. resources-light.png：技能/MCP/扩展

图中扩展页面包括范围、搜索、已安装/社区标签、扁平结果列表、安装按钮、分页、资源状态和刷新。包名、简介、作者与分页均来自真实查询。技能/MCP 复用组件外观，按各自现有配置语义显示路径、启用状态、诊断、安装/更新/移除，不把三类强行映射为同一种 npm 操作。

图里方块 Pi 图标是生成模型添加的装饰，正式实现用简洁包图标即可；不下载/伪造包品牌。安装期间显示进度，按现有不可取消语义处理包操作，不能给无效取消按钮。

## 7. oauth-light.png：认证动态问题

页头返回、provider 名、认证方式、浏览器步骤、动态问题输入和底部继续/取消。图中的“授权码”只是一种可能的动态 prompt；必须按原生 OAuth 事件显示文本/secret/选项问题和进度。只有事件要求输入才出现输入表单；不能所有 provider 都假定同一套 OAuth 步骤。外部认证链接交系统浏览器，WebView 不导航到外站。新密钥/secret 回复提交后清空表单内存。

## 交互与验收

一个统一 Back 入口：键盘 → 当前面板/抽屉 → 未保存提示 → 页面导航 → 回 Launcher。弹窗使用可访问的对话框语义与焦点管理；支持 prefers-reduced-motion，短淡入/位移不超过 180ms。按钮禁用须有原因，错误显示在当前操作附近。

这些图片已检查：主要中文文字可读，布局与组件关系明确；实际数据、动态问题和部分生成图里的系统栏/装饰按以上规则替换。设备截图、构建结果和剩余功能差异在完成实现后另行记录，不能把设计图当作设备验收截图。
